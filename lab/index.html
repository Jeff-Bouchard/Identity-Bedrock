id: privatenessID · sovereign identity · universal trust anchor explorer.emercoin.com/nvs/id/ ↗

NVS KeyValueDescription
id:username WORM XML · worm:id:1.0 Root identity record. Contains public key, on-chain creation block, optional Skywire pubkey. The universal trust anchor — all downstream trust chains here. Referenced bare (no prefix) in CAA issue tags to terminate TLS trust on-chain instead of in X.509.

worm: World Object MaRkup Language · canonical XML schema registry explorer.emercoin.com/nvs/worm/ ↗

The worm: prefix holds canonical XML schema definitions for every WORM document type. Every WORM record's <schema> tag value is the worm: NVS key of its governing schema.

worm:node:1.0 node: ✓ Specified

All WORM documents share a common <meta> block: <schema> pointing to a worm:*:* NVS key, <created> timestamp, and an ownership reference (<author> or <owner>) pointing to an id: key. Every record is traceable to a sovereign identity without revealing personal information.

dns: EmerDNS · SRV · CAA · A records explorer.emercoin.com/nvs/dns/ ↗

NVS KeyValueDescription
dns:_inference._tcp.<host> SRV RR RFC 2782 SRV for TCP inference endpoint. Format: priority weight port target. Multiple nodes under the same label → RFC 2782 load balancing and failover.
dns:_inference._skywire.<host> SRV RR SRV for Skywire mesh transport. Port 0 by convention. Target is <skywire_pubkey>.skywire.
dns:_prng._tcp.<host> SRV RR SRV for PRNG service endpoint. Same priority/weight/port/target structure.
dns:<host> A / AAAA RR Address record resolving the SRV target hostname.
dns:<host> (CAA) CAA RR The issue tag carries the bare id: NVS key of the authorizing identity. Trust terminates on-chain — no X.509, no root CA, no corporate hierarchy. Client-side enforcement in PrivatenessTools. 
EmerDNS NVS values# Address
dns:batman1.private.ness               "A 198.51.100.42"

# SRV — inference over TCP
dns:_inference._tcp.batman1            "SRV 10 100 8080 batman1.private.ness"

# SRV — inference over Skywire (port 0 = transport-native)
dns:_inference._skywire.batman1        "SRV 10 100 0 02abc...def.skywire"

# SRV — PRNG service
dns:_prng._tcp.batman1                 "SRV 10 100 7777 batman1.private.ness"

# CAA — issue tag = bare NVS key, no prefix before id:
dns:batman1.private.ness (CAA)         '0 issue "id:username"'
CAA trust chaindns:batman1.private.ness CAA  '0 issue "id:username"'
  │
  ▼  pull from NVS
id:username                   WORM XML → Ed25519 / ML-DSA-65 pubkey
  │
  ▼  verify
node TLS / Noise cert         must be signed by above pubkey
  │
  ▼  trust established
inference traffic flows
Client-side enforcement only. Standard DNS resolvers do not enforce CAA on behalf of clients. The check is PrivatenessTools-explicit: resolve CAA → pull id: WORM → verify node cert. Any client that skips this step accepts unauthenticated nodes.
