The Problem: Centralized AI Has 5 Kill Switches

🔑
Provider-revocable API keys. One ToS violation, one subpoena — the provider-issued key stops working. Identity keys remain owner-revocable; the point is that NESS removes third-party revocation power from the client path.
👁
Prompt logging by default. "We don't log" is a ToS promise, not a cryptographic guarantee. Every word you send is observed.
📄
ToS as the kill switch. A unilateral document the provider changes at will. Specific topics, jurisdictions, or users terminated by policy update.
🌍
BGP-reachable = geofenceable. api.openai.com resolves to IPs that can be blocked by DNS, firewall, or ASN filtering.
💳
Fiat payment = traceable. Every inference call backed by a credit card or KYC exchange account. The financial trail is surveillance infrastructure.

Three NVS Record Types

Include = verified node. dns:batman1.private.ness (CAA) → "0 issue \"emc:id:jeff_ness\"" # REQUIRED — WHAT: capabilities + pricing (WORM XML) inf:node_<hash> → <worm type="inf">...</worm>
6-Step Discovery & Verification
1
NVS prefix scan dns:_inference._tcp. → node list
2
Pick node per RFC 2782 priority/weight (load balance + failover built-in)
3
[Optional — if CAA present] Pull CAA → "emc:id:jeff_ness". No CAA = anonymous node, skip to 5.
4
[Optional — if CAA present] Pull id:jeff_ness NVS WORM → operator public key.
5
Open TLS/Noise. If CAA verified: check cert. If anonymous: connect without cert chain (user assumes risk).
6
Pull inf:node_<hash> WORM for model/pricing. Start sending tokens.

Open Problems — Honest Tradeoffs

⚡ Latency
Skywire mesh adds hops. Consumer hardware = 10–30 tok/s for 7B Q4 models. Not viable for real-time chat. Acceptable for async, batch, privacy-critical tasks.
🎯 Model Quality Ceiling
Sovereign nodes run quantized 7B–13B. Not GPT-4, not Claude 3.5 Sonnet. Sovereignty-grade, not benchmark-grade. Honest tradeoff: unrevocability for raw capability.
🔐 Privacy advantage
Compared with centralized APIs, NESS removes the revocable key, default prompt-logging trust gap, centralized kill switch, and fiat-facing account trail from the client path. That is a structural privacy advantage, not a marketing promise.
🔒 Provider Reputation Protocol
No protocol yet authenticates node output integrity at scale. A reputation system is specified, but unresolved.
⚠️ CAA Client Enforcement
CAA trust verification is client-side in this stack (non-standard). Clients that skip steps 3–4 connect to unverified nodes. Must be a hard requirement in PrivatenessTools client library.
Next paper after Identity Bedrock: The provider reputation protocol — a chain-anchored attestation system that aggregates signed reviews without a central authority.
